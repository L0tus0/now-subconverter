# HomeRouter 自动容灾

`config/HomeRouter.ini` 的普通代理默认路径为：

```text
应用分流 → 🚀 节点选择 → ♻️ 自动容灾 → 当前可用节点
```

自动容灾使用官方 `fallback`，按香港、美国、日本、台坡、其余节点的顺序筛选实际节点。它优先使用顺序靠前且健康检测可用的候选，不以最低延迟为唯一目标。地区测速组仍保留为可选项，所有自动组的检测间隔为 60 秒。

候选直接来自节点，避免嵌套缺少节点的地区组：subconverter 可能为这种空组填入 `DIRECT`。末尾的 `REJECT` 使没有任何匹配节点时拒绝连接，不会把普通代理自动回退为直连。重叠的名称匹配由转换器去重。

## 保留的分流

- AI 节点范围和 ChatBot 选择方式保持原样。
- 巴哈姆特继续使用台湾组。
- 土耳其商店继续保持原有固定出口选择，避免支付过程跨出口。
- 直连规则、应用规则的顺序和其他选择组保持原样。

## OpenClash 设置与迁移

- 关闭“Smart 策略自动切换”，使用官方 Meta/Mihomo 内核。
- 对首次建连迟缓的线路，关闭“统一延迟”，让测速结果包括建连耗时。
- 本地“URL-Test 间隔修改”若启用，会覆盖模板中的 60 秒；请确认最终运行配置。
- 已有用户的面板选择会被缓存。更新模板后，需要将 `🚀 节点选择` 切到 `♻️ 自动容灾` 一次；这是选择自动策略组，不是固定某个节点。
- 如果应用组曾单独固定为某地区或节点，它不会因主组改变而自动跟随。按需要把普通应用组设回 `🚀 节点选择`，保留上述专用分流。

## 边界

地区和节点名称不保证入口独立，应结合实际订阅的服务器地址、解析结果和测试记录确认。节点商改变入口后，需要重新评估备用路径。

`fallback` 根据健康状态选择后续连接，不承诺对当前失败请求无缝重试；已有 TCP 会话也不能迁移到新出口。它没有历史失败率评分或故障冷却隔离，偶发失败仍可能发生。本改动扩大自动候选范围并提供优先级回退，不能修复节点服务端或中转链路。

## 验证要点

使用真实 subconverter 检查生成配置，而不只检查 INI 文本：

1. 混合地区订阅中，容灾候选按上述顺序出现，节点不重复，不包含 `DIRECT`。
2. 只有美国节点时，容灾组包含该节点和 `REJECT`，不引用空地区组。
3. 用官方 Mihomo 校验生成 YAML，并在隔离实例验证健康首选、首选故障后回退、首选恢复后的选择。
4. 实网测试覆盖多个自动检测周期，同时记录业务成功率与实际选路；一次测速通过不代表持续稳定。

# HomeRouter 按入口分组自动容灾

在线订阅转换必须独立输出可运行的完整 YAML。本地入口聚合是可选增强，不是让配置能够启动的必需步骤；没有安装脚本的兼容 Mihomo 客户端也应能正常使用原有分流及自动测速。在线阶段不应根据转换服务器所在 ISP 预先认定客户端的入口拓扑，也不替换节点的原始服务器域名。

未经本地脚本处理的默认路径为 `🚀 节点选择 → ♻️ 自动容灾 → 🧩 入口候选（URLTest）→ 节点`。其中“入口候选”是包含实际节点的可用自动测速组，不是悬空占位符。应用规则和专用分流在这一基础配置中已经完整存在。2026-09-27 已使用 SkyNexus 的实际原始订阅验证全部组引用，并通过官方 Mihomo v1.19.31 完整配置校验；这证明配置可加载，不代表每条机场线路的可达性。

本地聚合后的路径：

```text
应用分流 → 🚀 节点选择 → ♻️ 自动容灾（fallback）
                          ├─ 入口 A（url-test）→ 此入口下的最快可用节点
                          ├─ 入口 B（url-test）→ 此入口下的最快可用节点
                          └─ 入口 C（url-test）→ 此入口下的最快可用节点
```

组内按延迟自动选择，容差 150 ms；外层按入口组优先级选择可用组。不会因为香港节点在列表靠前，就把所有香港节点排列在其他地区之前。各组检测间隔为 60 秒，入口组开启主动检测，并显式关闭切换时主动中断已有连接。

## 入口分组方式

`scripts/openclash_entry_groups.rb` 在 OpenClash 配置生成时读取实际订阅，用直连 DNS 查询节点服务器的 IPv4 地址。同一入口地址归入一个 URLTest 组；多地址域名之间只要有共同地址，就合并为同一组，包括传递交集。同一 IP 的不同端口也保守地归在一起。

解析失败、私网地址或 FakeIP 不会被当作独立入口，而是集中到最后的“入口未确认”组。只生成有实际节点的组；没有候选时使用 REJECT，不会通过空地区组意外变成 DIRECT。“机上”“免认证”等特殊用途节点不进入普通自动候选池。

这是按**可观察的入口 IP**划分故障范围，不是对线路物理独立的保证：不同 IP 仍可能共用机房、运营商或中转。节点域名的地址会在配置重生成时重新核对，不在运行过程中实时跟踪 DNS 变更。本实现针对 IPv4 入口，拒绝在全局 IPv6 启用时生成这类分组。

## OpenClash 安装

1. 将 `scripts/openclash_entry_groups.rb` 保存到 `/etc/openclash/custom/openclash_entry_groups.rb`。
2. 在现有 `/etc/openclash/custom/openclash_custom_overwrite.sh` 的 `exit 0` **之前**加入下列调用，保留已有覆盖逻辑：

   ```sh
   ruby /etc/openclash/custom/openclash_entry_groups.rb "$CONFIG_FILE" || LOG_OUT "Error: ingress grouping failed"
   ```

3. 可选配置 `/etc/openclash/custom/entry-groups.yaml`：

   ```yaml
   dns_server: 223.5.5.5
   core_gid: 65534
   priority: []
   ```

   `dns_server` 应与实际代理入口解析使用的直连 DNS 一致。查询子进程使用 `core_gid` 绕开 OpenClash 的 DNS 重定向；如路由器采用其他 GID，应相应修改。`priority` 可填经过验证的入口 IPv4，决定外层顺序；未列出的入口按地址排序。优先级不随每轮测速改变；组内节点持续自动测速。这个文件仅存放在路由器，仓库不需要包含订阅凭证或机场域名。

4. 使用 `config/HomeRouter.ini` 更新订阅并重新生成配置。主组选择 `♻️ 自动容灾` 一次，之后无需手选节点。检查运行配置：外层应引用多个 `🧩 入口 …` URLTest 组。

模板单独使用、尚未安装脚本时，会通过“入口候选”全节点 URLTest 组工作；这不具备按入口分组的容灾能力。若脚本报错，也保留这一基础策略，不退回原来的平铺节点 fallback。

脚本在订阅更新和配置重生成时执行；仅快速重启旧的运行配置不会重新解析分组。脚本和设置位于自定义配置目录，不修改 Mihomo 二进制，普通内核替换不需要重新打补丁。升级固件或重置配置前仍应备份自定义目录。

## 保留的分流与设置

- AI/ChatBot 节点范围、巴哈姆特台湾组、土耳其商店固定出口方式保持原样。
- 原有应用分流和规则顺序保持原样。入口分组仅作用于普通自动代理路径。
- 地区 URLTest 组仍保留为可选项；检测间隔 60 秒，原有容差保持不变。
- Smart 策略自动切换关闭，使用官方 Meta/Mihomo；关闭统一延迟，让测速包括首次建连耗时。
- 应用组若已单独固定为某节点/地区，不会自动跟随主组，专用分流除外可按需改为主组。

## 边界与验证

外层 fallback 使用各入口组的健康状态，内层 URLTest 选择该入口下的节点。节点测速失败后，组内仍有可用节点时可以留在该入口；入口组健康检测失败后外层才能选择其他组。健康状态存在检测延迟，不能保证当前失败请求即时重试；无法迁移已经断开的 TCP 连接，也不会按历史失败率自动冷却隔离入口。健康检查成功不代表所有业务请求成功。

运行 `ruby scripts/test_entry_groups.rb` 验证同入口合并、多地址交集合并、FakeIP/未知入口处理、空候选处理及专用分流保留。部署时还需用实际 subconverter 生成订阅并用官方内核校验，再在隔离实例验证：

1. 同一入口的多个节点自动选优。
2. 组内一个节点失败，其他节点仍可用。
3. 首选入口组不可用后，新连接转到另一个入口组。
4. 首选入口恢复后的自动回归。

短时 HTTP 测试不等同于手机视频播放验证，更不代表已解决入口或运营商的间歇故障。
